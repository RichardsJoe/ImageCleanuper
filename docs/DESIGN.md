# ImageCleanuper: design

A photo library you **search, filter and sort by tags** instead of browsing folders.
Photos stay where they are on disk. The app keeps a catalog (tags + thumbnails) on top of them.
AI suggests most of the tags; you only answer what it isn't sure about.

Clickable mockup: [`library-mockup.html`](library-mockup.html)

## Design guide (UI conventions)

Rules agreed while reviewing the mockup. New screens follow these.

### Buttons and actions
- **Adding something uses a small `+` icon button** on the header row it belongs to: `+` on a category header adds a tag, `+` on the Categories header adds a category. No wordy "+ Add …" buttons in panels or lists. Every icon button has a tooltip and screen-reader label ("Add a tag to People").
- An icon button whose inline box is open shows the accent colour until it closes.
- Inline add boxes open right under their header and get focus straight away. **Every add box can be cancelled**: Enter saves; Esc, the small × after the Add button, or clicking the same `+` again cancels; clicking away from an empty box closes it.
- Inputs and their focus rings are never clipped by the edge of a scrolling column.
- **Managing a category** uses a `⋯` button on its header that opens a small options box under it: Rename (inline box, prefilled), Color swatches, and Delete category… Delete always shows an inline confirmation that says what happens ("Delete People and its 5 tags? The tags are removed from 19 photos. The photos themselves are not touched."). Year is automatic and has no menu.
- **New categories are suggested and get their icon automatically.** A hidden library of 5,000 common category names, each with an icon (`docs/category-library.js`, generated by `docs/build-category-library.py` from a curated core plus the lists in `docs/category_data_extra.py`), drives suggestions as you type, most common first ("ca" → Cats, Cars, Camping…). Apostrophes are ignored and multi-word input matches word starts ("kids soc" → Kids' soccer). Names tied to a specific year ("Summer 2025") are left out because they go stale; "Class of" years are the exception. Pick one with the mouse or arrow keys + Enter, or type your own. The icon is assigned automatically: exact library name, else word by word (last word first, filler words like "pics", "weekends", "and" and numbers only as a last resort), checking a table of ~800 everyday words, nicknames and abbreviations ("bday" → cake, "xmas" → gift, "vacay" → plane, "doggo" → paw, "nationals" → trophy) and words shared with library names, falling back to a plain tag. Renaming re-picks it. The colour is the next one not already used. **A new category slots into the list alphabetically** (before the first category that sorts after it) and is **highlighted for 5 seconds** (outline + tint, scrolled into view, then fades) so the user sees where it went and can drag it elsewhere. **Categories the library doesn't know are learned**: they're added to the user's own library with their icon and suggested first from then on. The user never manages icons.
- Destructive actions use the danger colour and never happen in one click.
- **Esc closes the topmost thing first**: full-size viewer, then any open menu or box, then the details panel.
- Full text buttons are only for the main page actions ("+ Add folder", "Start tagging", "Done").

### Lists of tags
- Tags are **A–Z by default**. Each category has its own sort toggle on its header (A–Z → Z–A → Most photos). Year defaults to newest first.
- **Favorites:** a ☆ appears on hover (always visible on touch screens). A starred tag moves to the top of its category, with a thin line under the favorites.
- **The list never reshuffles while filtering.** Tags keep their place. Counts update, and tags with no matching photos are greyed out instead of removed.
- **Categories collapse** from their header. Category headers show no counts, open or collapsed (selected tags are already visible as chips in the search box).
- **Categories reorder by dragging** the ⠿ handle (or with the arrow keys). While dragging, a floating copy with a shadow follows the pointer and a dashed outline shows where it will drop.

### Layout and scrolling
- The header and search bar stay fixed. The category column and the photo grid each scroll on their own; scrolling one never moves the other.
- **No scrolling inside scrolling.** Categories never get their own scrollbars; the category column scrolls as one, and keeps its position when the list redraws. Long categories can be collapsed instead.
- The category column is resizable with a drag handle between it and the grid (260–520 px). **Labels never overlap or get cut off**: long category names wrap onto up to three lines; dragging narrower than 260 px snaps the column to a slim icon strip (56 px). Click an icon to reopen the column at that category, click » to reopen it, drag it back out, or double-click the divider (double-click toggles between strip and full column). A dot on an icon means that category has selected tags.
- **Every category has an icon** in its colour (People: person, Places: pin, Events: calendar with star, Things: box, Year: calendar, your own categories: tag). The same icon shows on the full header, so the strip is easy to read. Widths, order, sort, collapsed state and favorites are remembered.
- **Scrollbars never cover content.** Every scrolling area reserves its own lane for the scrollbar plus a small gap, so photos, counts and stars are never under it (this matters on Windows 11, where scrollbars float over content by default). Scrollbars are thin and themed.
- Headers in a column line up: name on the left, small controls (sort, `+`) on the right, in the same positions on every row.

### Photo details
- Opening a photo docks its details as a column on the right. **The grid stays usable**: click any other photo to switch to it in one click, with no dimmed background and nothing to close first. The open photo is outlined in the grid.
- **Click the preview to open the photo full size** (hover shows "Open full size"). The viewer fills the screen on a dark background, with ← / → buttons and arrow keys to step through the results, and × or Esc to go back. The details panel follows along.
- Prev / Next buttons and the left/right arrow keys step through the current results. Esc or Close hides the panel. On a phone the panel fills the screen.

### Settings
- **Getting there:** a gear icon (top right, next to "+ Add folder"), plus shortcuts from where you are: "Manage all categories…" in a category's ⋯ menu, "Settings › AI tagging" in the Add photos dialog. Settings replaces the library view; "← Library" or Esc goes back.
- **Layout:** sections on the left (Photo folders, Backups, AI tagging, Categories, Tags, Appearance, Data & privacy), settings in cards on the right. A dot on a section means something in it differs from the default.
- **Every setting can go back to its default.** A small ↺ appears beside any setting that's been changed; its tooltip says what the default is. Each section has "Reset section". "Reset all settings" (with an inline confirmation that lists what's reset) never touches photos, tags or categories themselves.
- **AI tagging section:** choose AI tagging or Manual only; connect / replace / remove the Claude API key (stored in Windows Credential Manager, never in a file); monthly spending limit; what to tag; most tags per photo; how cautious.

### Search
- Selected tags appear as coloured chips inside the search box, in front of the typed text. Remove a chip with its × or Backspace.
- An **×** at the right end of the search box clears all chips and text (Esc does the same). It only shows when there is something to clear.
- Commas and spaces both separate search words.

## Workflow

1. **Add folder.** Pick a folder and choose what Claude should tag. Nothing is moved or copied.
2. **Auto-tag.** Photos are sent to Claude (small copies, using the user's own API key, within their monthly spending limit) in the background. The library is usable while it runs. **Without an API key the app runs in Manual only mode**: photos are added untagged apart from what's stored in the file, and the user sorts and tags them by hand.
3. **Answer a few questions.** These are grouped so one answer covers many photos: "Who is this? (46 photos)", "Name this event? (212 photos)", "Hide 38 screenshots?"
4. **Find.** Use the search box, tag filters (People / Places / Events / Things / Year) and sort (newest, oldest, recently added, favorites).
5. **Fix as you go.** Open a photo to add or remove tags and to accept or dismiss suggestions. Select several photos to tag them all at once. Your edits are locked and the AI never overrides them.

New photos added to a watched folder are picked up and tagged automatically.

## AI tagging pipeline (the input side)

**There is no local AI model.** Automatic tagging needs a Claude API key; without one the app is Manual only. A few things don't need AI at all and always run on the computer: reading the date and GPS stored in the file, turning GPS into a place name, and spotting exact/near duplicates by comparing images.

Each stage writes tags with a **source** (`ai`, `user`, `file`) and a **confidence**.
High-confidence tags are applied (at most 5 per photo, see Backlog). Medium-confidence tags show as *Suggested*. Low-confidence tags are dropped.

| Stage | Produces tags like | How |
|---|---|---|
| Date & time | `2024`, `July`, `Morning` | File data (no AI): EXIF date, then file name, then file dates; Claude only for undated photos (e.g. old scans) |
| Places | `Cape Cod`, `Home` | File data (no AI): EXIF GPS → place name; you can name places like "Home". Claude can suggest a landmark when there's no GPS |
| Duplicates | `Duplicate`, `Burst` | No AI: image fingerprints (exact + near) |
| People | `Emma`, `Mom` | See open decisions: needs a way to group the same person across photos |
| Pets | `Biscuit` | Claude describes the animal; you name your pets |
| Events | `Beach trip 2024`, `Christmas` | Group by time gaps + location, holiday calendar; Claude suggests a name; you confirm or rename |
| Things & scenes | `Beach`, `Cake`, `Sunset`, `Snow` | Claude, choosing from your categories and the tag library |
| Junk & quality | `Screenshot`, `Blurry`, `Receipt` | Claude, plus simple sharpness/brightness checks |
| Text in photos *(optional)* | words found in the image | Claude reads the text |
| Old scans *(optional)* | `Old photo`, `1987` | Claude spots scans and estimates the decade; rotation/splitting is image processing |

### More options to consider later
- **Natural-language search** ("Leo at the lake last summer"): Claude turns the sentence into tags and filters.
- **Smart albums.** Saved searches that update themselves ("Emma + Birthday").
- **Best shot picker.** In a burst or duplicate group, pick the sharpest photo with eyes open.
- **Write tags back into files** (XMP/IPTC keywords) so other apps see them too.
- **Family tree-style names.** Link "Mom" to a person, with an age estimate for date guessing on old scans.
- **Colour / mood tags** and **video** support (keyframe tagging).

## Open decisions
- Platform: Windows desktop app (like before), or a local app used in the browser.
- Should "Add folder" also offer to copy photos into one library folder, or always leave them in place?
- Which AI taggers are on by default (the mockup turns on everything except reading text and old scans).
- **People with no local AI:** Claude can describe who is in a photo but doesn't match faces across photos. Options: the user tags people by hand (with "tag everyone in these selected photos"), the user names a person once per event and the app spreads the name within that event, or add a dedicated face-grouping service later. To decide.
- First-run: ask for the API key up front (with "I'll tag by hand" as the alternative), or let people browse first and ask when they add a folder?

## Backlog

Agreed ideas that are deliberately **not built yet**. Pick these up when reviewing the backend processes.

### Tag library and AI tag limit
- **Tag library:** apply the same approach as the category library to tags. A large list of first names is fine. A large hidden list of popular tags (common first names, places and landmarks, objects, activities, events, holidays…), each linked to the category it belongs in. It powers suggestions while typing a tag (same matching rules: most common first, ignores apostrophes, multi-word word-starts) and helps file a new tag into the right category automatically. **Any tag the user types that isn't in the list is added to it** (learned, like new categories), so it's suggested from then on.
- **AI applies at most 5 tags per photo** when it processes images. The user can add as many more as they like by hand. This keeps auto-tagging focused and easy to review.
- Open questions for then: how the 5 are chosen (highest confidence, or one per category first?); whether tags under that limit still show as *Suggested*; whether people's names come from the user's own contacts/naming rather than a generic list; and where the list is stored and updated (shipped file vs. downloaded).
